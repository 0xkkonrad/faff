Nine verified issues were fixed. Three independent agents reviewed model/storage behavior, browser usability, and performance/PWA behavior, then cross-checked the other reviewers' findings. The release preserves the existing design, IndexedDB schema, saved histories, and active timers.

## Confirmed

| ID | Severity | Failure scenario | Fix and evidence |
| --- | --- | --- | --- |
| M1 | Medium | Window B restores a backup that removes the date or session in window A's open dialog. A throws and keeps obsolete controls. | Close stale dialogs before rendering restored state. Confirmed twice: independent verifier and parent browser reproduction. Regression covers both deleted days and deleted sessions. |
| B1 | Medium | Keyboard users commit, start, pause, or resume; replacing the control moves focus to the document body. | Focus the corresponding next timer action. Add a persistent completion announcement. Confirmed twice; regression checks focus through completion and rating. |
| B2 | Medium | Rate a session, then open options while Undo is visible. The toast covers dialog controls and its button remains usable outside the modal. | Hide the undo toast while a dialog is open, retaining Undo until its original expiry. Confirmed twice; pointer and keyboard regressions pass. |
| P1 | Medium | Returning to a window with years of history deep-copies and validates every historical session, then rebuilds an unchanged view. | Copy only modified days; preserve previous state; skip unchanged view replacement; calculate the streak once per render. Confirmed twice with synthetic browser benchmarks. |
| B3 | Low | Reload a history URL; it opens the timer, or loses the selected historical date. | Share hash parsing and recover the validated date from browser history. Independent verification and today's/past-date regressions pass. |
| B4 | Low | Import a JSON file containing `null`; it exposes an internal exception message. | Show the intended invalid-backup message. Existing data remains unchanged. Independent verification and regression pass. |
| M2 | Low | Reopen and end a day repeatedly; the 25th partial session makes End fail despite having available session slots. | Remove the inappropriate completed-session cap from partial history. Parent reproduced the old failure; independent verification and 30-partial regression pass. |
| P2 | Low | A remote change arrives through both BroadcastChannel and localStorage, causing two transactions and two complete repaints. | Remember the highest pending revision and skip a redundant read after catching up. | P3 | Low | An idle page rewrites the identical document title four times per second. | Write only changed titles and poll once per second. Independent verification measured zero idle title mutations; regression passes. |

## Refuted with evidence

- **Oversized toast from conflicting top/bottom CSS:** a later stylesheet sets `top:auto`. Actual measured height was 46 px. The separate modal overlap was real and fixed.
- **Landscape backup controls are unreachable:** scrolling the sheet exposes the controls at 667 × 375, and keyboard dismissal works.
- **WebKit's automated offline reload failure indicates a Waffle regression:** the same failure occurs with the old release and a minimal service worker that returns literal text. Both Waffle versions and the minimal page work when the server is actually disconnected. Chromium passes both disconnection methods. See [the WebKit comparison](qa-2026-09-22/webkit-offline.json).

## By design — do not fix

No finding was closed by a RULING-grade decision. The documented local-only storage model, 30-minute sessions, shared daily allowance, and best-effort background alarms were preserved as existing product behavior.

## Reassuring negatives

- All 13 model tests pass, including immutable state snapshots, rejected-action isolation, midnight ownership, daily ceilings, corrections, and more than 24 partial sessions.
- The original Chromium browser suite passes: timer/pause/reload, plan edits, rating/undo/correction, offline operation, calendar/streaks, backup download/restore, concurrent rating races, midnight rollover, and small/large layouts.
- All 12 focused browser regressions pass in Chromium and WebKit, covering the repaired behavior, unchanged-view refresh, and idle title stability. Each case uses a fresh browser process to avoid a reproduced WebKit failure while creating its fifth context in one process.
- Two independent reviewers ran 8,000 and 10,000 differential state transitions against the baseline using frozen inputs. Accepted outputs matched, excluding the deliberate partial-limit change. Sixty concurrent writes converged without stale state or browser errors.
- A real baseline-to-new release migration and the repeatable PWA update suite preserve running, paused, and awaiting-rating timers. Both open windows update; the previous shell is removed; offline reload retains timer state and history.
- New tests run in source-repository CI. Screenshots were checked for the mobile modal and desktop timer; no design change was introduced.

## Open rulings

No product decision is required for this release. Physical-device installation, screen readers, notification delivery, wake locks, and true Android/iOS suspension were not tested. WebKit offline emulation has the limitation described above; real-device Safari offline behavior is not claimed.

Large histories still require a full IndexedDB read and validation. Bursts of focus/visibility/pageshow events can still perform two reads, though they no longer repaint unchanged content. Recommendation: keep the current storage schema unless real usage shows that the remaining cost warrants migration. A ten-year synthetic history still takes roughly 143 ms to synchronize at 4× throttling.
